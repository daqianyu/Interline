# 开发设计

## 共用原则

沿用 `Chapter.readingText` 的稳定 UTF-16 坐标；布局变化不改原文。
使用现有目录/正文分离、不可变正文文件、后台分页、缓存与回滚日志。
对用户可见的状态，在所需持久化成功后再发布；失败保留原文件、输入和可恢复证据。
新结构采用可读旧数据的版本迁移，不做无理由的全量框架替换。

## D01：保护损坏的 UserDefaults

影响：`ReadingStorage.save`、新的故障回归测试；不修改现有存储键与 JSON schema。

步骤：

1. 将通用保存的类型约束收紧到 `Codable`，以同一目标类型验证原值。
2. 先编码新值，防止新值自身无效时产生无意义恢复副本。
3. 原值不存在或可解码时照常保存；原值为坏 JSON/错误属性类型时先封存。
4. 在 `Recovery` 原子写入二进制 plist，包含原始 `key` 与 `value`。
   Data 类型的字节原样保留，其他 UserDefaults 属性列表类型也保持类型与值。
   文件名仅由 UUID 构造，禁止把外来键直接拼成路径。
5. 封存失败则拒绝覆盖，保留原键值并报告保存失败；成功后才能设置新值。
6. 复用现有原始文件导出入口。封存不是自动修复；不声称已恢复损坏内容。

兼容：保持现有偏好、书签、记录的读写格式；有效数据不新增恢复文件。
不把 UserDefaults.set 的返回当作底层磁盘耐久性证明，异常断电仍需专门验证。

## D02：真实的回滚状态

影响：`AppState.restoreLibraryBackup` 的失败分支、故障测试。

1. 失败后检查 `recoverInterruptedRestore()` 的结果。
2. 回滚成功：说明备份未导入成功，原有资料保持/恢复；允许后续操作。
3. 回滚失败：明确“恢复与回滚尚未完成”，引导数据管理的恢复重试；
   保留日志，依赖现有 `permitWrite` 阻止相关写入，不使用“资料已保留”的成功断言。
4. 清除故障后，重试须恢复目录、笔记、草稿、偏好和阅读记录，并解除写屏障。

测试通过真实临时文件障碍模拟失败，避免只测试文案枚举或伪造成功标志。

## D03、D05：草稿与目标章节

- 设计串行存储任务，以草稿 ID 和递增版本区分新旧输入；后台结果不能覆盖较新输入。
- 编辑器保留内存文本；短窗口合并写入，显示“保存中/已保存/未保存”。
- 保存笔记、取消、退出、进入后台时刷新待写；明确强杀前未落盘输入的边界。
- 不让异步旧草稿在笔记提交/删除草稿后重新出现；提交与清理建立顺序屏障。
- D05 复用正文加载器异步读取/验证目标章节，取消后不写入，错误保留编辑器。
- 本项涉及维护事务：先规定后台草稿与备份/恢复的互斥，再实现，不使用两个无协调写通道。

### D03 实施细化（D01/D02 验收后开始）

1. AppState 分开保存已落盘草稿和待写输入，按草稿 ID 合并；每次输入递增版本。
   300 ms 无新输入后启动单一写循环，批量保存当前最新快照。写入中有新输入时，
   只清除与已写版本一致的待写项；旧结果不能把新输入标成“已保存”。
2. ReadingStorage 增加后台草稿写入入口；编码、原文件校验、损坏原文封存和原子写入
   在后台完成。沿用 drafts-v1.json，不迁移 schema；封存失败仍拒绝覆盖。
3. 存储层记录草稿写入占用，阻止同步草稿替换及事务开始/回滚与后台文件写入重叠。
   AppState 在备份/恢复前设置维护屏障、刷新草稿，失败则不开始维护。同步删除/清理
   遇到待写或失败输入时明确要求先保存重试，不丢弃待写文本。
4. 编辑器展示“保存中 / 已保存 / 未保存”，错误留在当前页并有重试。
   保存笔记或取消前等待刷新；未成功不关闭。提交后再清理草稿，清理失败可再次保存。
   待写期间禁止交互下滑关闭；离开/应用变为非活跃时触发刷新。
5. 系统强杀、立即挂起和磁盘故障不保证未落盘字符可恢复；文案明确只有“已保存”
   状态代表成功，真机后台时限仍需验证，不把内存缓存称为持久化。
6. 测试使用可控制的后台写入边界和真实临时文件，覆盖合并、写入中继续输入、故障重试、
   提交后不复活、备份刷新和维护互斥；UI 覆盖取消后重启恢复与保存状态。

本项不顺带实现 D05（目标章节异步读取）；提交笔记时该独立性能问题仍保留在计划中。

## D04、F07：备份演进

- 第一阶段加入前置体积检查和逐书处理，记录峰值；硬限制仍保留。
- 第二阶段采用 manifest + 独立正文/附属数据的文件包，避免全集合同时展开。
- manifest 记录 schema、条目、尺寸、校验信息及完整/部分状态；校验路径和资源上限。
- 保留 v1 JSON 恢复；新版导出与恢复往返测试通过后再成为默认格式。
- 单书损坏可选择部分导出，展示遗漏清单；默认完整导出不得静默跳过。
- 恢复先预览新增/保留/冲突，再事务合并。当前资料优先原则保持；冲突不覆盖。
- 取消、磁盘不足、包损坏、中断恢复均要有可验证的结果，不向用户暴露内部实现术语。

## D06、Q01–Q04：错误与验证基础

页面操作返回结构化结果，页面内展示错误和重试；减少在 sheet 内仅使用全局 Toast。
日志不收集正文或私人笔记。CI 保存编译日志、xcresult 和截图，区分编译、业务失败、
runner 启动失败和超时；有依据才重跑，不自动忽略失败断言。
真实文件提供器、VoiceOver 和能耗用例见测试设计，需外部设备的项目独立记录阻塞。

### 第一轮回归阻塞：Q04 的测试同步子步骤

CI 39638159549 中 82 项单元测试通过，笔记重启 UI 用例在目录未呈现时失败。
失败层级仍包含 readerTOC 和正文，没有分段控件；录屏的重启后正文有保存的高亮。
原始 Synthesized Event 记录点击 (59, 845.43)，而稳定后的目录按钮范围是
x=37–81、y=769–813；点击使用了动画期间尚未稳定的位置，落在最终按钮下方。
这不是笔记丢失的证据。修正测试的同步缺口：
等待编辑器真正消失；工具按钮可点击且位置稳定后只点击一次；独立断言目录呈现，
随后仍严格验证笔记数量和原文。保留动画和原来全部测试，不用重复点击或无条件重跑。
本子步骤不提前关闭 Q04，也不宣称 U03 界面改造已经完成。

复验 39645321845 的第一次稳定性采样耗时约 4.3 秒，5 秒预算内没有第二次采样。
调整为先确认按钮存在并取得初始位置，再在 15 秒窗口内验证可点击与稳定位置；
这是针对已观察到的自动化查询延迟，不改变目录呈现和笔记持久化的业务验收条件。

### Q04：可审查的 CI 失败摘要

- 新增无第三方依赖的 Python 日志摘要工具，输入 build.log、测试步骤 outcome 和 job 状态；
  生成 JSON/Markdown，附失败信号、去重测试汇总行和明确的人为复核建议。
- 类别为成功、测试失败、构建失败、运行器失败、明确超时、取消、未知失败、无日志。
  断言超时属于测试失败，不能归为基础设施超时；混合信号全部保留。看到失败断言时
  不允许因最终取消而掩盖它；没有证据则标未知，不猜测是环境问题。
- 不采集正文/私人笔记，不复制完整日志到摘要，仅保留错误类型标记及测试数量汇总。
  原始 CI 日志和 xcresult 仍按原流程作为测试证据保存。
- workflow 先运行分类器自身的单元测试，构建后无论结果均尝试生成摘要，连同现有
  产物上传；取消路径也尽力保留摘要。runner 被强制终止时不保证后续步骤能执行。
- 摘要不决定 xcodebuild 的退出码、不添加自动重试、不跳过 UI 测试。应用编译/业务
  证据对应其实际源代码；纯 CI 工具改动另列本地测试及后续 workflow 集成结果。

## P01–P04、A01–A03：书库与状态

- P01 以实际阅读记录判定继续阅读，导入日期仅用于导入排序；兼容旧记录。
- P02 本书笔记关联草稿 ID，显示未完成数量，复用同一编辑器，避免产生两个草稿版本。
- P03 增加独立完成状态，明确旧数据迁移策略；显示进度与用户决定分开。
- P04 集合使用稳定书 ID；批量操作逐项结果可恢复；列表/网格、排序筛选持久化。
- A01 渐进抽出阅读会话、书库、笔记和维护组件，限制可写属性；每次拆分保持行为测试通过。
- A02 先收集 Q03 数据。若整书解码构成瓶颈，再制定正文新版本和章节索引迁移，
  分别验证搜索、导出、恢复和旧正文读取。若无必要，保留测量结论，不能假称已优化。
- A03 扫描所有引用集合后生成清理候选，默认不自动删除；排除恢复资料与进行中操作，
  清理失败可重试，核验并发导入场景。

## U01–U09：界面开发

- U01：列表按钮的内容显式使用语义文字色，匹配词用局部强调；不以颜色作为唯一状态。
- U02/U03：优先原生 toolbar/searchable，验证 SDK 后采用优先级/溢出；阅读工具显示时
  不改变原文锚点，收起后无遮挡。常用动作保留，次要动作不凭空删除。
- U04：常用与高级分组，预览、重置和退出保持位置；结合 F05 的预设模型。
- U05：调整渲染层对空段与段距的处理，canonical text 不变；必要时显式维护布局映射。
- U06：先将首段操作命名准确，再增加触点定位和原地选择；验证选区、字体、旋转、跨页边界。
- U07：语义字号、可变布局、至少 44 pt 命中区域；大字时允许换行/收起次要操作。
- U08：实际中文字体确认后命名，不能把系统设计请求当作特定中文字体保证。
- U09：导入封面规范化、尺寸限制和缓存；TXT 封面保持简单；用户封面支持恢复默认。
