# 测试与验收设计

## 环境与通用门槛

- 编译：Xcode 27、iOS 27 SDK、Swift 6；记录实际版本和运行 ID。
- 自动化：按修改范围运行必要回归；涉及阅读、存储或路由时运行完整现有单元/UI 套件。
- 截图：视觉修改至少检查书架、阅读、相关弹窗；浅/深色、窄屏、横屏、最大字号。
- 真机：取得签名后记录机型、系统、数据样本、操作和结果。当前无签名，不填写通过。
- 数据：使用临时目录和独立 UserDefaults suite；故障测试绝不破坏用户真实数据。
- 每项失败修复后针对受影响用例复验；没有新改动/失败/风险时不无意义重复测试。

## 第一轮详细用例

| 用例 | ID | 前置与操作 | 必须观察到的结果 |
|---|---|---|---|
| T-D01-01 | D01 | 写入损坏书签 JSON，启动后添加书签 | 新书签成功；恢复 plist 包含原键与逐字节相同的 Data；重启可读新值 |
| T-D01-02 | D01 | 偏好/阅读记录写入错误属性类型或损坏 Data，再保存 | 原类型/值可导出；新值可正常解码；键名不进入文件路径 |
| T-D01-03 | D01 | 将 Recovery 目录路径设为普通文件，尝试替换损坏书签/设置/记录 | 保存失败；原始值完全不变；可见状态不宣称成功 |
| T-D01-04 | D01 | 重复保存有效书签、设置、记录 | 不产生恢复副本；新值正确读取 |
| T-D02-01 | D02 | 事务中变更目录/偏好后中断，恢复路径被目录障碍阻断，再尝试恢复备份 | 回滚失败提示明确，不声称已保留全部资料；日志保留；继续写入被拒绝 |
| T-D02-02 | D02 | 清除上述临时障碍，执行恢复重试 | 目录、笔记和偏好回到事务前；日志移除；写入重新可用 |
| T-D02-03 | D02 | 可正常回滚的失败路径 | 不报告“仍需回滚”；原资料与读取状态一致 |
| T-D02-04 | D02 | 无事务时输入无效备份 | 原资料不变，失败原因可见；不能产生虚假待恢复状态 |

测试需验证真实保存/恢复行为，不只断言实现内部调用次数。所需测试名和 CI 证据
在执行完成后登记到 `04-final-acceptance.md`。

第一轮 UI 复验保持 9 项原有用例。笔记重启用例需确认编辑器关闭、工具栏按钮可点击
且位置稳定、目录弹窗呈现、笔记计数为 1、内容为原输入；失败立即停止该用例并留存证据。
不删除持久化断言，不以多次点击目录掩盖第一次点击失败。

## D03 详细验收用例

| 用例 | 操作 | 预期 |
|---|---|---|
| T-D03-01 | 连续更新同一草稿 100 次，立即刷新 | 合并写入最新值；落盘前不标已保存；重启读到最终输入 |
| T-D03-02 | 暂停第一次后台写入，再输入新版本，然后释放写入 | 旧结果不清除新输入；最终文件和已保存状态对应新版本 |
| T-D03-03 | drafts 路径设置为目录障碍，输入并刷新，再清除障碍重试 | 原资料不被替换；输入留在内存且显示未保存；重试后正确落盘 |
| T-D03-04 | 存在待写输入时提交笔记，再检查草稿与重启结果 | 笔记完整保存，草稿清理后不会被旧写任务重新创建 |
| T-D03-05 | 输入尚在合并窗口时导出备份 | 导出前刷新，备份包含最终草稿；刷新失败则导出失败，不声称完整 |
| T-D03-06 | 写入尚未完成时尝试同步草稿替换、事务开始或删除 | 操作被明确拒绝；旧任务不能跨越事务屏障污染新库 |
| T-D03-07 | 原草稿文件损坏，再异步保存 | 原字节封存后才替换；封存失败保持原文件 |
| T-D03-08 | UI 输入、取消、重启后从数据与存储恢复草稿 | 关闭前保存完成，原输入和摘录仍在；可见保存状态与结果一致 |

后台文件操作通过真实写入验证，不以计数替代内容检查。模拟器验证非活跃刷新流程，
系统立即终止/真机后台时限不承诺零丢字，单独保留待验证条件。

## 无障碍检查细化

Q04 分类器单测必须覆盖：成功、编译错误、断言失败、断言等待超时、运行器启动失败、
无测试运行的基础设施超时、取消、未知/缺失日志、混合失败信号、重复测试汇总去重、
输出 JSON/Markdown 与原始敏感文字不进入摘要。用两次实际失败日志复核测试失败分类。
CI 需上传摘要；退出状态继续由原测试步骤决定，分类器不能把失败变成成功。

Q02 的逐页操作、环境组合和证据要求见 [无障碍检查矩阵](06-accessibility-matrix.md)。
已建立矩阵不代表通过实际检查；最终须结合 U07 回归后才能关闭 Q02。

## 性能记录规范

固定样本包括：普通中文书、接近 TXT 上限的大书、多章节书、100 本书元数据、
大量笔记/草稿、接近备份上限的数据。报告设备、系统、构建、样本规模和重复次数。
先测现状再设置有依据的耗时/内存预算；不得把此前元数据测试的秒数写成真机冷启动。

## 失败与发行判定

数据丢失、错误覆盖、不可恢复位置、阻断主流程的失败均阻止相关范围验收。
无障碍/性能缺陷按影响列优先级。每个失败附复现步骤、版本、预期/实际、日志、
修复提交及复验结果。没有签名时可以“代码与模拟器通过”，不能“最终发行通过”。
